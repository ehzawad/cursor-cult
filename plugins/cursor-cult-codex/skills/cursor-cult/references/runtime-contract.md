# Runtime contract

`roles.json` is a non-empty array of host-created role objects with `id`, `label`, `instruction`, optional `mode`, optional `model`, and optional `mode_reason`. `context.md` must contain the required Intent Capsule headings and a Current Phase Brief. Both files share one private user-owned `0700` staging directory.

The runner strips Cursor API-key variables by default, probes Cursor CLI browser login, tolerates unknown NDJSON fields, and requires a non-empty terminal result for success. Role sessions are scoped by canonical project, host session key, and role ID. Confirmed stale resumes retry fresh once.

Detached `start` owns one supervisor process and persists `state.json`, per-role results, reports, and `events.ndjson`. The event schema is `cursor-cult.event.v1`. The default heartbeat is 540 seconds; tests or operators may override it with `--heartbeat-seconds` or `CURSOR_CULT_HEARTBEAT_SECONDS`. The supervisor schedules the next heartbeat after each interval completes, so lock waits, filesystem latency, and operating-system suspension accumulate delay: this is a liveness cadence, not a hard real-time deadline, and a run shorter than one interval emits no heartbeat. Heartbeats report run age and role counts but do not falsely claim task progress. Role transitions and terminal outcomes are appended and fsynced as they occur; when a reader observes them depends on its own poll interval. A dead recorded supervisor is reconciled to one persisted `run_failed` event; terminal status is absorbing, so a supervisor that loses the startup-grace race exits rather than reopening the run. Best-effort liveness uses PID existence, so PID reuse can make a dead supervisor look alive.

`watch` is a read-only event transport for one run. `watch-all` is a session-length transport filtered by project and optional host session key. Both flush one JSON object per line; terminal state is carried in the event rather than conflated with watcher transport failure.

Exit codes: `0` success, `3` partial success, `1` failure, `2` invalid invocation/precondition, `130` cancellation. `watch` exits `0` after observing any terminal run event, and also exits `0` when the run is already terminal with nothing newer than `--after-sequence` to deliver; inspect the event's `status` and `details` for the run outcome.

Read-only enforcement is fail-closed and independently enforced. Every non-writer role runs against its own Cursor configuration, supplied via `CURSOR_CONFIG_DIR`, denying `Write(**)` and `Shell(*)`; Cursor applies deny rules ahead of allow rules and ahead of `--force`, so containment no longer rests on whether `--mode` outranks `--force`. Shell is denied because it bypasses a `Write()` deny; `--readonly-shell` relaxes it. In addition, `ask`/`plan` roles are still refused with exit `2` when `cursor-agent --help` does not advertise `--mode`, since omitting `--mode` is how agent mode is selected.
